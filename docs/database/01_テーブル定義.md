# テーブル定義書（社員管理システム）

## 1. Users テーブル

### 1.1 概要

ログイン認証および権限管理に使用するユーザー情報を管理するテーブル。

### 1.2 カラム定義

| カラム名     | 型            | 必須 | PK | UNIQUE | 説明           |
| -------- | ------------ | -- | -- | ------ | ------------ |
| id       | BIGSERIAL    | ○  | ○  | -      | ユーザーID       |
| email    | VARCHAR(254) | ○  | -  | ○      | ログインメールアドレス  |
| password | VARCHAR(60)  | ○  | -  | -      | ハッシュ化済みパスワード |
| role     | SMALLINT     | ○  | -  | -      | ユーザー権限       |

### 1.3 制約

* PRIMARY KEY：`id`
* UNIQUE：`email`
* NOT NULL：`email`
* NOT NULL：`password`
* NOT NULL：`role`
* CHECK：`role IN (0, 1)`

### 1.4 値制約

* `role`

  * `0`：EMPLOYEE
  * `1`：ADMIN

### 1.5 CRUD仕様

#### CREATE

* 新規ユーザー登録時に、ログインに必要なユーザー情報を登録する。
* 管理者による社員登録時に、対応するログインユーザー情報を登録する。
* CSVインポートによる社員登録時に、対応するログインユーザー情報を登録する。

#### READ

* ログイン認証時に、メールアドレスを検索キーとしてユーザー情報を取得する。
* JWT認証時に、ユーザーIDを検索キーとしてユーザー情報を取得する。

#### UPDATE

* 社員のメールアドレスを変更する場合は、Usersテーブルの`email`も更新する。
* パスワードおよび権限の更新処理は、現時点では実装しない。

#### DELETE

* 管理者による社員削除時に、対応するユーザー情報を物理削除する。
* Employeesテーブルの社員情報とUsersテーブルのユーザー情報を、同一の処理内で削除する。

---

## 2. Employees テーブル

### 2.1 概要

社員番号、氏名、メールアドレス、部署、役職、入社日および在籍状態を管理するテーブル。

管理者による社員情報の登録・更新・削除、CSVインポート、社員自身の情報取得・更新処理で使用する。

### 2.2 カラム定義

| カラム名            | 型            | 必須 | PK | UNIQUE | 説明                       |
| --------------- | ------------ | -- | -- | ------ | ------------------------ |
| id              | BIGSERIAL    | ○  | ○  | -      | 社員ID                     |
| user_id         | BIGINT       | ○  | -  | ○      | Usersテーブルに対応するユーザーID     |
| department_id   | BIGINT       | ○  | -  | -      | Departmentsテーブルに対応する部署ID |
| position_id     | BIGINT       | ○  | -  | -      | Positionsテーブルに対応する役職ID   |
| employee_number | VARCHAR(20)  | ○  | -  | ○      | 社員番号                     |
| name            | VARCHAR(50)  | ○  | -  | -      | 氏名                       |
| email           | VARCHAR(254) | ○  | -  | ○      | メールアドレス                  |
| hire_date       | DATE         | ○  | -  | -      | 入社日                      |
| status          | VARCHAR(20)  | ○  | -  | -      | 在籍状態                     |

### 2.3 制約

* PRIMARY KEY：`id`
* UNIQUE：`user_id`
* UNIQUE：`employee_number`
* UNIQUE：`email`
* NOT NULL：`user_id`
* NOT NULL：`department_id`
* NOT NULL：`position_id`
* NOT NULL：`employee_number`
* NOT NULL：`name`
* NOT NULL：`email`
* NOT NULL：`hire_date`
* NOT NULL：`status`
* FOREIGN KEY：`user_id REFERENCES users(id)`
* FOREIGN KEY：`department_id REFERENCES departments(id)`
* FOREIGN KEY：`position_id REFERENCES positions(id)`
* CHECK：`status IN ('ACTIVE', 'RETIRED')`

### 2.4 値制約

* `status`

  * `ACTIVE`：在籍
  * `RETIRED`：退職

### 2.5 CRUD仕様

#### CREATE

* `ADMIN`は社員情報を新規登録できる。
* CSVインポートにより社員情報を一括登録できる。
* 社員登録時に、対応するUsersテーブルのユーザー情報も登録する。
* 社員登録時は、部署および役職に対応するIDを`department_id`と`position_id`に設定する。

#### READ

* `ADMIN`は社員情報を全件取得できる。
* `EMPLOYEE`は自身の社員情報を取得できる。
* `EMPLOYEE`は社員一覧画面で、社員の氏名、メールアドレス、部署および役職を取得できる。
* 部署および役職を表示する場合は、DepartmentsテーブルとPositionsテーブルを参照する。

#### UPDATE

* `ADMIN`は社員情報を更新できる。
* `EMPLOYEE`は自身の氏名およびメールアドレスのみ更新できる。
* 画面から社員情報を更新する場合は、`Employees.id`を検索キーとして使用する。
* 社員のメールアドレスを更新する場合は、Usersテーブルの`email`も同時に更新する。
* CSVインポート時は、既存社員情報を更新できる。

#### DELETE

* `ADMIN`のみ社員情報を物理削除できる。
* 社員情報を削除する場合は、対応するUsersテーブルのユーザー情報も削除する。

### 2.6 登録・更新ルール

* 画面から社員情報を更新または削除する場合は、`Employees.id`を検索キーとして使用する。
* Usersテーブルとの関連付けには、`Employees.user_id`を使用する。
* Departmentsテーブルとの関連付けには、`Employees.department_id`を使用する。
* Positionsテーブルとの関連付けには、`Employees.position_id`を使用する。
* CSVインポート時は、`employee_number`を基準として新規登録または更新を判定する。
* CSV内の社員番号がEmployeesテーブルに存在しない場合は、新規登録する。
* CSV内の社員番号がEmployeesテーブルに存在する場合は、既存社員情報を更新する。
* `id`はデータベースによって自動採番されるため、CSVの登録・更新判定には使用しない。

## 3. Departments テーブル

### 3.1 概要

社員が所属する部署情報を管理するマスターテーブル。

### 3.2 カラム定義

| カラム名 | 型           | 必須 | PK | UNIQUE | 説明   |
| ---- | ----------- | -- | -- | ------ | ---- |
| id   | BIGSERIAL   | ○  | ○  | -      | 部署ID |
| name | VARCHAR(50) | ○  | -  | ○      | 部署名  |

### 3.3 制約

* PRIMARY KEY：`id`
* UNIQUE：`name`
* NOT NULL：`name`

### 3.4 値制約

* `name`

  * `GENERAL`：総務
  * `HR`：人事
  * `PLANNING`：企画
  * `SALES`：営業

### 3.5 CRUD仕様

#### CREATE

* `ADMIN`は部署情報を新規登録できる。
* 使用する部署情報は、初期データとしてあらかじめ登録する。

#### READ

* `ADMIN`は部署情報を取得できる。
* `EMPLOYEE`は社員情報の表示に必要な部署情報を取得できる。
* 社員登録画面および社員更新画面で、部署の選択肢として取得する。
* 社員一覧画面で、社員が所属する部署を表示するために取得する。

#### UPDATE

* `ADMIN`のみ部署名を更新できる。
* 部署情報を更新する場合は、`Departments.id`を検索キーとして使用する。

#### DELETE

* 現時点では部署情報の削除処理を実装しない。
* 削除処理を実装する場合は、Employeesテーブルから参照されている部署を削除できないものとする。

### 3.6 登録・更新ルール

* 部署情報の登録および更新は、Departmentsテーブルに対して行う。
* 社員情報を登録または更新する場合は、選択された部署の`Departments.id`を取得する。
* 取得した`Departments.id`を`Employees.department_id`に設定する。
* CSVインポート時は、CSVに記載された部署名から対応する部署情報を検索する。
* 取得した部署IDを`Employees.department_id`に設定する。
* CSVにDepartmentsテーブルに存在しない部署名が記載されている場合は、エラーとする。
* CSVインポートによって、Departmentsテーブルを自動登録または更新しない。

## 5. テーブル間の関連

各テーブルは、Employeesテーブルが保持する外部キーカラムを使用して関連付ける。

### 5.1 Usersテーブルとの関連

```text
users.id
   ↑
employees.user_id
```

* `Users.id`と`Employees.user_id`を関連付ける。
* 1件のユーザー情報に対して、1件の社員情報を関連付ける。
* `Employees.user_id`にはUNIQUE制約を設定する。

### 5.2 Departmentsテーブルとの関連

```text
departments.id
   ↑
employees.department_id
```

* `Departments.id`と`Employees.department_id`を関連付ける。
* 1つの部署には、複数の社員が所属できる。
* 1人の社員は、1つの部署に所属する。

### 5.3 Positionsテーブルとの関連

```text
positions.id
   ↑
employees.position_id
```

* `Positions.id`と`Employees.position_id`を関連付ける。
* 1つの役職には、複数の社員を関連付けることができる。
* 1人の社員は、1つの役職を持つ。

### 5.4 関連図

```text
Users
- id PK
- email
- password
- role
       1
       │
       │
       1
Employees
- id PK
- user_id FK
- department_id FK
- position_id FK
- employee_number
- name
- email
- hire_date
- status
       │
       ├──────── 多対1 ──────── Departments
       │                       - id PK
       │                       - name
       │
       └──────── 多対1 ──────── Positions
                               - id PK
                               - name
```

### 5.5 関連付けに関する注意事項

* `Users.id`と`Employees.id`は直接関連付けない。
* `Users.id`と`Employees.user_id`を関連付ける。
* `Departments.id`と`Employees.department_id`を関連付ける。
* `Positions.id`と`Employees.position_id`を関連付ける。
* 各テーブルの関連は、アプリケーション側だけでなく、データベースの外部キー制約によって保証する。
* 社員情報、部署情報および役職情報をまとめて取得する場合は、JOINまたはJPAの関連付けを使用する。
